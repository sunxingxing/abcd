## Blocking Findings

### R1 / P1: --value-source can be ignored by option order

`tools/abc_semantic.cc:553-581`: the `--value-source` branch does not reject an
already selected detail mode. `--exception-template --value-source` reaches
`Inspect(...detail)` without the required policy and can invoke the legacy
exception template emitter. The reverse order rejects the combination.
This breaks A01 rather than merely changing diagnostics.

Fix: parse all options, validate combinations independent of order before any
file access, and pass the selected policy explicitly. Reject duplicate and
conflicting source forms. Add CLI regression specifications for both orders
of every prohibited detail/value combination; do not run them during the pause.

### R2 / P1: completion and stage receipts can certify an unproved route

`source_route.cc:39-49` accepts a child marked Complete with only Decoded (or no
stage), and ignores `legacy_writer_used`. The test explicitly approves this
state at `source_route_test.cc:136-139`. `RouteStageLedger::Advance` ignores its
route and allows a legacy ledger to claim TreeVerified or a fresh ledger to
jump directly to Published. Consequently the proposed evidence gate can close
without a verified tree, contrary to acceptance.md section 2.

Fix: central typed receipt validation, route-specific permitted transitions,
explicit complete-stage requirements (Printed/Published for emitted products),
failure/coverage consistency, and rejection of ValueTree plus legacy-writer use.
Use the validator in parsing and obligation closure. LegacyAllowed permits an
otherwise valid completed Legacy OR ValueTree child; it is not RequireLegacy.
Define whether TreeVerified-only artifacts are separately represented rather
than making them indistinguishable from emitted complete source.

### R3 / P1: receipt identity is insufficient to bind evidence to input

`source_route.h:77-85` contains only entity offsets. Standalone receipts lack
content hash, profile identity, source contract and engine/rules provenance;
the same numeric method in another file is indistinguishable. Child closure
checks only its numeric method. The enclosing structure manifest supplies some
context, but abc_semantic's standalone receipt does not, and the API does not
require a matching envelope. This fails T00's identity contract.

Fix: define a typed input/evidence identity, using existing fingerprint/profile/
source-contract types and truthful version fields. Require identity in a receipt
or a validated, explicit envelope for both tools. Work revisions not yet created
at admission must be typed absent, never invented. Child obligations must bind
to the expected input/context, not only method number. Do not pretend current
single profile enum independently certifies three unrelated profile versions.

### R4 / P2: reverse parsing accepts truncated and missing evidence

`source_route.cc:11-15,82-100`: unsigned JSON integers narrow to uint32/unsigned
without bounds checks. A schema of 4294967297 can become 1 on this platform,
and method/record/PC offsets can alias valid offsets after truncation.
`source_route.cc:131-166`: missing or nonboolean legacy_writer_used silently
becomes false; missing failure becomes no failure. Malformed evidence therefore
gets safer-looking defaults rather than a typed rejection.

Fix: exact integer-range validation before conversion; required fields and
strict types; validate nullable fields separately from absent fields; reject
contradictory receipts with the validator from R2. Include oversized integers,
wrong types, missing fields and contradictory states in unexecuted regressions.

### R5 / P2: requested route is checked after legacy-specific analysis

`tools/abc_semantic.cc:350-366` calls BuildSemanticMethod before admission. A
valid decoded method with handlers or another unsupported legacy semantic shape
can exit with a legacy semantic error instead of the requested T00 refusal.
The no-form branch also emits a legacy summary before its receipt. The receipt
comments claim nothing beyond decode ran, which is inaccurate.
`BuildRecordSource` has no RoutePolicy parameter, while `abc_structure` fabricates
its refusal directly instead of consuming an authoritative route decision.

Fix: for T00, route admission immediately after the minimum required identity/
decode steps, before legacy analysis or emission; one unambiguous receipt
product. Carry an explicit policy through the public record entry and establish
an invocation-context rule for descendants, so later stages do not silently
reset policy through default arguments. CLI serializers must consume the actual
typed failure, not hard-code its current enum reason. Keep existing legacy
behavior under LegacyAllowed, and do not implement T01 prematurely.

### R6 / P2: a new test assertion is guaranteed to fail

`tests/unit/source/source_route_test.cc:109-110` compares variant::index() with
RouteReceiptError::kIdentity (2). The variant has only alternatives 0 and 1.
The expected error can never satisfy the assertion.

Fix: check the error alternative and compare its contained enum. Also correct
the positive completion examples affected by R2. Add actual guarded-entry/CLI
regression specifications rather than treating the pure admission helper alone
as proof of no legacy fallback. Tests remain unexecuted unless the user resumes.
