# Member Access Spelling

The common printer now selects dot notation for constant ASCII IdentifierName
keys and quoted bracket notation otherwise. `MemberKeySyntax` is a typed output
choice at the necessary textual property-name boundary, not dispatch on source
fragments or opcode names. The existing pool-reference/string decoder resolves
the key once. ASCII letters, underscore and dollar sign can start an identifier;
digits may follow. Keywords are legal after a dot. Unicode, malformed-surrogate,
empty, whitespace and punctuation keys retain exact UTF-16 string escaping.

This choice is restricted to member reads, writes, already-proved own-field
writes, receiver calls and staged receiver calls. It does not select object
literal, class member or binding declaration syntax: `__proto__` and
`constructor` have distinct special cases there. The original IsElementName
rejection remains; shorter spelling does not grant new by-name/index semantics.
Dynamic keys are unchanged.

Receiver parentheses and property References remain intact. Getter counts,
call receiver, key value, assignment descriptors and argument evaluation order
are unchanged. Output passes through the existing Text cursor and budget, so
positions describe generated bytes directly rather than a postprocessed string.
Classification and printing cost O(key units), O(1) additional scratch beyond
the existing decoded string and output storage. No new cache or dependency is
introduced.

Both production CLIs build and read-only review found no concrete defect.
ABC-only export of unchanged pasteboard modules.abc to untracked
`build/pasteboard-member-access-01` retains eight incomplete application records
and the two host-constructor refusals at PC14. Combined source size falls from
198,115 to 194,770 bytes, with 11,422 lines unchanged. Logger now prints `.debug`,
`.domain`, `.prefix` and `.format` through the shared call/field paths.

Tests, generated JS execution and RSS measurement remain paused. Deferred
regressions include keyword/$/_ keys, empty and Unicode keys, lone surrogates,
numeric key refusal, getter/Proxy observation, receiver identity, own-field
semantics, output limits and generated positions. This is source-generation
evidence, not completed source style or semantic-equivalence validation.

## Class Method Names

The callable printer now uses a separate `ClassifyMethodKey` boundary for
already-admitted MethodDefinitions. It reuses ASCII IdentifierName spelling
but keeps `constructor` and `prototype` computed regardless of placement.
These grammar-sensitive exclusions do not replace class ownership, layout or
descriptor checks, and do not grant admission to previously rejected members.
Object data properties and class field declarations do not use this decision.

Ordinary, async, static and accessor prefixes are preserved. Keywords are
valid MethodDefinition names, including contextual `static`, `async`, `get`
and `set`; the key and SetFunctionName result do not change. ASCII characters
pass through the existing output budget; other UTF-16 names retain computed
string-literal escaping. Cost is linear in key length with constant scratch.

Both production CLIs build and read-only review found no concrete defect.
ABC-only export to `build/pasteboard-method-keys-01` preserves eight incomplete
application records and both host-constructor refusals at PC14. Logger emits
`debug(...args)` and ProgressBar emits `get curBp()` and
`set progressInfo(newValue)` with the same recovered parameters and bodies.
Tests, JS execution and RSS measurement remain paused. Deferred checks cover
ordinary/async/static/accessor combinations, contextual keyword keys,
constructor/prototype exclusion, Unicode escaping, method names/lengths and
output exhaustion. This change does not establish full source equivalence.
