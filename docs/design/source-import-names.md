# Source Import Names

## User Intent

The user clarified that previous VM-boundary questions were not understood and
requested decompilation in the original source style. Treat this as a source
readability requirement, not blanket approval of additional host invariants.
Prefer original bindings, imports, classes, signatures and structured bodies;
do not ask the user to decide implementation-level VM details without explaining
their application-level consequences. This change does not alter superclass
admission, the source-contract version, or erased-type recovery.

## Record-Owned Plan

The shared BuildRecordSource path reads regular and namespace import local
names from ABC module metadata. RecoverImportNames builds one slot-indexed plan
and a sorted nonempty-name index, retained through synchronous descendant
emission. No sidecar source or user-provided import text is an engine input.

Strict ASCII binding validation reuses the existing identifier/reserved-name
boundary. Well-formed but unsupported names, duplicate local names and names
matching any same-record runtime callable/class name retain $importN. An
unreadable or malformed string entity remains a typed metadata failure, not
an invented name or unsupported-bytecode classification. All callable names
are indexed once, including methods not reached during this particular export.

The prelude preserves original request traversal and module slot numbering.
Default and namespace imports use the selected local binding; a named import
whose imported/local names match omits the redundant `as`. No snapshot alias
or additional dependency is created: module reads continue to use live ESM
bindings. Legacy detached record output retains its existing private names.

GlobalScope borrows the slot plan and sorted index. The common printer, nested
linear/lexical writers and imported constructors in literal graphs consume
the same spelling. If recovered formal names collide with an admitted import,
the function owner uses its existing private ABI formal names for that formal
list, protecting reads in this function and descendants. Runtime callable/class
name collisions were excluded when building the plan. Generated lexical cells,
registers and module locals remain in their private namespace. Global-name and
trusted-realm lookup checks reject shadowing by an admitted import rather than
silently resolving to the wrong binding.

The plan reserves a bounded allocation beside the existing record body and
export plan. Actual vector capacities and owned string capacities are charged;
one string parse is live at a time. Slot lookup is O(1), name collision checks
are binary searches, and construction is O(M log M + E log E + E log M + S)
for M methods, E imports and S decoded name text. Storage is O(M + E + S)
during planning and O(E + S) retained. No method bodies are eagerly decoded
for this naming pass and no new dependency is introduced.

## Evidence And Limits

Production abc_semantic and abc_structure targets built. ABC-only pasteboard
export through --shared-source recovered original import names in all eight
currently emitted source files; none of those sources contains $import.
For example Home imports TipsDialog, pasteboard, abilityAccessCtrl,
bundleManager, BreakpointType, CommonConstants, Logger and hilog. Logger's
logging methods call hilog directly. Declaration and use names changed together.
The reviewed export replaces out/pasteboard-latest rather than accumulating
another retained historical output directory.

Publication remains eight incomplete sources, two refused constructors and
nine metadata-only records. Position artifacts retain 195 methods and 9,745
spans, regenerated by the printer with the new identifier lengths. These
counts do not establish full semantic equivalence or exact mapping correctness.

Tests, generated JS execution and RSS tracking remain paused. Deferred focused
regressions: default/named/namespace imports, request order, duplicate/invalid
bindings, callable/class/formal collisions, nested closures, imported literal
constructors, newly shadowed globals/realm bindings, malformed string entities,
budget exhaustion, 200/201 scaling and generated-position changes. EntryAbility
body recovery and type-only imports absent from ABC are not solved by this pass.
