## Constructed evidence and test-tool correction

`tests/support/abc/builder.py` now supports prepaid empty tagged literal arrays
in both the file literal index and regional method/literal reference pool.
Existing defaults serialize byte-identically. The two-pass writer keeps checked
arithmetic, output/scratch charging and checksum generation. Pool method 0 is a
real method; string 1 and empty tagged literal 2 are real entries. Frame bounds,

undefined test registers are **not** valid runtime object inputs. The fixtures

its full lift result, input roles, effects and commits are saved. The new test

correction, with no production decoder behavior change.

## Prioritized implementation backlog

These are proof-work estimates, not completion promises. Exact distinct-record
impact is below. Do not sum variants to estimate family containment.

1. **APPLY argument-array construction**, upper bound 3 current first-refusal
   records under each contract. Cross-layer, medium/large: prove the entire fresh
   argument array and receiver/reference/effect order, then remove the internal
   array without exposing its intermediate effects. `RuntimeCallSpread` at
   `runtime_stubs-inl.h:2675` requires a callable and JSArray, then
   `RuntimeGetCallSpreadArgs:2857` obtains an iterator, with a stable-array copying
   fast path and a step/value loop otherwise. Native `f(...args)` for arbitrary
   values would change accepted inputs, acquisition/next effects and fast-path
   holes/iterator behavior. That unconditional premise was declined. Use the
   premise-free whole-construction proof only; no new approval assumed.
   NEWOBJAPPLY differs again: `RuntimeNewObjApply:337` requires a JSArray,
   snapshots its length, performs indexed Get in order and constructs with that
   list; it does not iterate the argument array. Native `new C(...a)` therefore
   also needs the whole-construction/iterator-unobservability proof, not an
   unconditional spread replacement. Range calls keep their real receiver and
   argument count and need no spread premise.
2. **Measurement gaps in primitive/width variants**, small proof/test work:
   XOR, exponentiation, bitwise-not, unary ToNumber, typeof, BigInt and long
   branches. Existing raw lifts must be distinguished from missing source
   recovery. `TONUMBER` must preserve BigInt rejection (unary `+`, not Number());
   strict constants must avoid a mutable global lookup. Width equivalence needs
   branch/operand provenance and scale tests, not per-width source admission.
3. **This/super and indexed properties**, medium: reuse typed Get/Set/reference
   machinery, immutable frame receiver and home object. Super receiver differs
   from lookup base; computed key evaluation and throws remain ordered. Indexed
   uint32 runtime paths may pass a numeric key to a Proxy (see the existing
   [property evidence](isa-properties-runtime-evidence.md)); generic `o[index]`
   is not authorized without a receiver/path equivalence proof. Zero currently
   located first refusals in this fixed selection; this is ISA breadth work.
4. **Literal/object protocols**, medium: fresh object `__proto__`, CopyDataProperties
   (`{...x}`), exclusion/rest (enumerable own keys, symbols, order, getters), and
   tagged-template site identity (frozen raw/cooked arrays and per-site caching).
   Recover the whole private construction, not a mutable builtin call. RegExp
   literal opcode is an intrinsic allocation; global `new RegExp` is not an
   unconditional replacement. Invalid literal buffers/flags need typed refusal.
   Own-property definitions retain descriptor semantics, distinct from Set.
   Computed WITHNAMESET is still gated: the pinned numeric fast path can retain
   a numeric `.name`, while native property NamedEvaluation supplies a string.
   Either prove an equivalent string-key path/fresh anonymous value or seek a
   separate user decision; ISA 2c did not authorize the numeric difference.
   CALLRUNTIME_DEFINEFIELDBYVALUE additionally needs computed-key conversion and
   private-construction ordering, never an Object.defineProperty substitution.
5. **Module namespace/lazy and sendable widths**, medium: native import/namespace
   and the already approved ArkTS forms, preserving slot/request/domain, lazy
   timing, live binding, field/env identity and recompilation metadata. Shared
   or sendable cells cannot be erased to ordinary cells. No new premise is
   needed for a fully proven ArkTS round-trip; incomplete layouts stay refused.
6. **Private fields/initializer calls and method creation**, medium/large:
   private brand/env activation, class home object, inherited access, initializer
   receiver, name and descriptor semantics. Native `#field`/methods are faithful
   only with the full class proof. Never replace a brand check with public
   membership or a private initialization with ordinary assignment.
7. **Generator/async/iterator families**, large: 103 records contain the raw
   suspend/resume/await family, but normalized source already handles many of
   them. A raw UnsupportedInstruction here does not mean 103 blocked records.
   Reuse existing suspension/completion protocols; async iteration and close
   priority need their own full proof. Existing acquisition/Hole premises apply
   only within their approved scopes. Standalone close cannot be erased.
8. **Globals, arguments and lexical environment/rest**, medium: preserve
   declarative global vs global-object binding, mapped vs unmapped arguments,
   actual frame identity, parameter aliasing, cell activation and rest order.
   Native lexical/parameter syntax is conditional on those proofs; blindly
   emitting module-level `let` or a shadowable `arguments` is not equivalent.
The frame/intrinsic group also includes LDFUNCTION, LDTHIS and LDSYMBOL:
   source self/this/intrinsic references need lexical/receiver identity proofs;
   a mutable global `Symbol` lookup is not the same as the runtime intrinsic.
   GETUNMAPPEDARGS requires an unmapped arguments object and correct invocation
   scope, including reassignment/aliasing behavior. No bare identifier substitute
   is admitted by this evidence pass.
9. **Patch/frame/debugger and abrupt protocol checks**, specialized:
   patch variables belong to a live patch environment, not ordinary lexical
   bindings; LDNEWTARGET requires an execution-path profile as above. `debugger;`
   retains the runtime hook but Node cannot verify debugger callbacks. Throw
   checks belong to their original TDZ/const/super/destructuring/generator
   protocols; replacing them with a synthesized `new Error` may alter class,
   payload or observable construction. Retain typed refusal without that proof.

No new premise is requested by this evidence increment. Possible future user
choices must be separate: unconditional APPLY spread (already declined), indexed
Proxy-key differences, intrinsic-vs-mutable-global replacement, or patch-state
erasure. None is enabled here. The preferred route remains a proof that these
observable differences are absent, or a semantics-preserving output profile.
