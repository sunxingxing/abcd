# Literal Initialization

## Nested phased control arms share their original phi

Rule 125 indexes normal CFG paths in iterative successor-first order, retaining
all exceptional edges in the original graph. Original phi input edges seed
leaves; a branch closes compatible child paths into the existing SelectionChild
and SelectionRegion representations. Every original leaf edge and child has
one expression parent. Disjoint leaf counts therefore measure actual coverage,
not only matching cardinalities. Partial children keep the same merged phi;
only a complete enclosing family may own its actual eager consumer.

Predicate dependencies use the same inline/module root forest and root-use
prefix analysis as operand checking. Roots resolve through typed parent edges,
independently of operation storage order. The operand checker checks every
child's prefix, leaf identity, execution count and original catch/staging scope
before granting ownership to the enclosing group or its dependent expressions.
A control child has a typed parent and no invented eager input or intermediate
phi. The fresh checker reconstructs the records and child map.

Control binding retains the actual branch/header, selected arms and original
join. Tree construction obtains child decisions from the existing control
adapter: a phased Commit has no operation range and cannot supply a physical
last-operation predicate. Scalar identity predicates may combine origins on
their checked condition node; independent correspondence still validates all
origin membership. The same FunctionTree, ObjectExpr and printer emit nested
conditions and whole objects without an alternate writer.

This path currently composes closed acyclic expression families using existing
single-expression phi edge bundles and the existing operation-result predicate
representation. Direct entry/literal predicates need a representation extension;
this is not a language restriction. Multi-observation phi materialization,
shared reconvergent expression tails, general staged arrays and legacy
member-prefix/joint-suffix corridors retain representation gaps. No block
identity, register/PC layout, opcode sequence or fixed nesting count supplies
production semantics. A foreign effect or changed catch scope retains original
statements; it does not disappear to improve output style.

## Nested phased operands retain their final execution scope

Rule 124 separates a selection's actual syntax consumer from its execution
owner. A pure comparison may consume an inner selected value while its result
feeds an outer decision. The comparison has no exceptional dispatch and cannot
stand in for the original throwing consumer's scope.

Candidate selections are grouped by actual eager consumer and operand order.
The existing inline source roots connect each group to its enclosing candidate
selection. A bounded queue checks enclosing groups before their dependencies;
only a successfully checked parent supplies an execution owner. Cycles and
failed parents remain at their original placements. An ordinary inline subtree
uses its already checked source root. Syntax input, transport, merged phi and
original branch identities remain separate from this execution field.

Selected throwing arms and ordered predicate prefixes compare their original
catch/staging signature with that final owner. Existing def-use, conditional
arm, operand-order, Reference and inert-interval obligations remain binding.
The fresh verifier independently rebuilds groups and execution owners, including
rejection of a corrupted execution field. There is no optional-chain template,
opcode sequence, register/PC layout, producer list or selection-count admission.
The existing forest, object initializer and printer compose native conditional,
optional-member and object expressions without a new AST or writer.

For S candidate selections, grouping/sorting costs O(S log S); the dependency
queue adds O(S) work and O(O+S) storage for O operations, plus the existing
selection/corridor and catch-signature checks. Each group and dependency is
visited once. This does not remove legacy discovery, member-prefix or final
suffix corridor limits, and does not claim general nested-arm/array recovery.

## Phased predicates own their execution prefixes

Rule 123 indexes root-use equations for phased condition dependencies. A
reverse-use Kahn worklist resolves each source root only after all external
consumers have resolved to one terminal owner. Multiple uses inside that owner
are allowed; competing owners, unresolved cycles, phi-edge observations and
callee acquisitions do not acquire predicate-prefix ownership. Existing inline
subtrees and module pairs retain their previously checked roots and References.

Pure execution anchors expose each candidate prefix and its decision to the
same EffectOrder equations. Exact predecessor and must-reach successor
identities prove one complete ordered prefix on every normal path. Original
full-flow successful-Commit dominance proves each result available at the
decision; throwing roots retain the final consumer's original catch signature.
Anchors never claim a language effect or substitute for those obligations.
No single-entry corridor, same-block, adjacency, operation sequence or producer
list is required for this prefix proof. Independent operand checking recomputes
the index and prefix, while the existing forest emits the prefix within the
conditional expression and the existing object analysis composes the initializer.
Necessary snapshots preserve a raw VM predicate that tests a value more than
once without replaying its getter.
This placement represents ordered predicate evaluation and its pure dependencies.
Pure-only materializing snapshots keep their original placement; moving those
into assignment sequences adds syntax without composing an ordered evaluation.
Their eventual binding elimination remains a separate recovery gap.

The root-use worklist is O(O+U) work/storage. Grouped prefix sorting costs
O(P log P), followed by O(P+U) checking across disjoint root/use lists, plus the
existing EffectOrder/dominance costs. Every edge is indexed/processed once;
there is no per-condition CFG walk or fixed-point retry. Scratch and retained
capacity use the existing invocation budget; no dependency or proof/publication
wrapper is introduced.

Decoded three-profile regressions cover register aliases, copies and block
subdivision at 1/200/201/402 sizes. A foreign debugger event, an early return
after the getter and a potentially nonterminating pure loop refuse movement.
Cleared prefix ownership is rejected independently. Native object output is
executed against a separate instruction-semantics oracle over 769 combinations
of changed getter results and first/second-read failures, preserving raw
predicate behavior, original thrown identity, read count/order, fresh identity
and own descriptors.

Rule 123 alone did not compose nested selected values inside predicates.
Rule 124 adds the execution dependency described above; its actual paired VoIP
output now composes the optional scene and enum selection into the native object. The member-Reference prefix and joint-selection suffix
paths retain their documented legacy corridor limits. These are implementation
gaps, not language rules, and no new local patterns extend them here.

## Phased object initialization composes checked source operands

Rule 122 reuses `logical_objects` and the common ObjectExpr forest for staged
objects whose RHS expressions have already acquired valid phase-expression or
selection ownership. LiteralPlan remains independently checked: allocation
identity, complete own-definition coverage and absence of early observation
are prerequisites. The allocation retains its original root and snapshot.

An iterative functional-forest walk resolves operation parents, selected phi
arms, checked module guard/read pairs and existing native nested initializers.
It rejects cycles and resolves each parent once. EffectOrder projects those
already owned operations into their source consumer event; exact predecessor
and must-reach successor identities then prove the complete definition chain
on every normal path. Projection alone cannot authorize folding: original
expression execution count, leaf identities and catch signatures are still
checked by their common owners. No block identity, adjacency, producer list,
selection count or serialization order is an additional admission condition.

One canonical use census checks each external source leaf at the original
allocation using full-flow dominance. A pure late snapshot remains late unless
its expression has actual source ownership; language membership alone does
not move a binding. Ordered throwing operands retain the original catch
signature, including catch copies. A nonthrowing allocation with later catch
staging still has the existing representation gap. Promoted definitions use
the common initializer placement; fresh verification reconstructs pre-fusion
statement consumers before checking RHS scheduling and recomputes the object
candidate independently. TreeFlow and operand checks consume the existing AST.

The ownership walk and census add O(O+U) work/storage, plus the existing shared
EffectOrder and catch-signature analysis costs. Actual capacities and work are
charged to the same invocation budget. There is no per-object CFG walk, new
dependency, private final IR or proof/publication wrapper.

Three-profile decoded fixtures compose conditional, getter, member-call and
TYPEOF operands, including 1/2/200/201/402 copies/definitions and register
aliases. Barriers, early observation and an unowned late snapshot remain
negative; forged final-definition ownership and missing object ownership fail
fresh verification. Independent JS executes 83 repeated member-call cases,
checking separately read callees, receivers, prior effects, original thrown
tokens, fresh identity and own descriptors. Computed `__proto__` keys retain
data-property semantics.

Unowned effectful predicate prefixes, general staged arrays and remaining
legacy nested/corridor paths are still implementation gaps. In particular,
the actual VoIP object's optional scene read still occurs as a separate prefix.
The fixed five ABCs have unchanged source bytes in both contracts; this general
capability does not close their remaining semantic or source-style acceptance.

## Phased initialization uses the shared all-path effect order

Rule 121 extends the existing EffectOrder to phased SSA. Its predecessor and
must-reach equations follow normal edges; original full-flow dominators prove
availability after the operation's successful Commit. Catch entries start
separate effect histories, even if a normal backedge reaches an entry. A typed
ValueReturn ends normal source execution despite its synthetic valueless Commit.
Neither a normal-only dominator tree nor a serialization position proves
availability on an exceptional path.

LiteralPath now uses this analysis for both ordinary and phased objects and
arrays. If every RHS is a language value already available at allocation,
exact predecessor identity and the next must-reach effect prove the definition
chain through pure splits, joins, copies and block subdivision. Once that proof
succeeds, no same-block, fallthrough corridor or adjacency condition is added.
The original def-use census still rejects an observation before completion,
including a catch copy of a partially initialized object. Catch signatures and
expression ownership remain separate obligations of the existing phased path.

Three-profile decoded regressions build complete exception trees and native
object/array expressions with 1/2/200/201/402 copies and definitions. Bypass,
getter barriers, potentially nonterminating pure loops and catch observations
do not acquire this capability. Independent JS checks preserve fresh identity,
prototype, input identity and own descriptors, including the computed
`["__proto__"]` key. Array numeric keys are resolved by the normal constant
boundary, rather than changing the expression forest's representation.

The existing iterative Kosaraju and sparse must-reach solver are reused; the
extension adds O(B+E+O) work/storage beyond the existing availability analysis,
with vector capacity charged to its original budget. There is no new dependency,
per-definition CFG walk, sample dispatch or proof/publication wrapper.

Late or conditional RHS expressions still use the old owned-expression path.
Its remaining corridor/nesting restrictions are implementation gaps; this
extension does not complete phased staged-to-native conditional objects.
The common printer can still retain an empty pure branch outside the literal.
That representation gap is not evidence of complete source-style acceptance.

It does not complete reconstruction of an
entire staged object as a native object literal.

## Staged statement operands use common expression scheduling

Rule 119 distinguishes allocation-owned native literal RHSs from staged
definitions that remain statement roots. Only native RHSs retain the literal
pin; staged RHSs use the existing local or phased operand scheduler. Independent
evaluation verification reconstructs the same ownership distinction before
checking all proposed edges. This is not permission to reorder the staged
object's allocation or definitions.

Phased consumers use DescribeEvaluation's eager input and source-lowering
capabilities rather than requiring a result-producing parent. Stored-value
reference boundaries, predicate snapshots, exclusive canonical uses, ordered
effect suffixes and actual catch-copy signatures remain binding. A resultless
consumer is the final execution owner; an effect subtree with no matching catch
evidence retains its snapshot immediately, preventing a failed outer fusion
from disturbing already valid inner Reference ownership.

Decoded three-profile tests combine a selected initializer with a later getter
RHS at 1/2/200/201/402 copies. The later getter becomes the field RHS directly;
debugger barriers and repeated consumers retain snapshots. Complete exception
trees and independent verification check original exceptions and ownership.
The Node oracle separately checks getter count/order, original thrown tokens,
fresh object identity and own __proto__ descriptors. This is operand fusion,
not completion of phased staged-to-native object reconstruction. The existing
producer capability and corridor limits remain implementation gaps.

No additional graph index or retained storage is introduced. Capability checks
are O(1) per existing operation/edge; the shared linear scheduling, retry and
catch-copy accounting retain their previous complexity and budgets.

The normal and phased routes share one indexed canonical-use census. Pure alias

snapshots of an unfinished object still refuse. Native normal field ordering uses
the common reverse-postorder position, not OpId sorting. Existing nesting,

define this capability.

Late owned expression trees retain the existing local normal interval; phased

representation gaps. This rule does not widen those paths by adding more shapes.

## Allocation-site availability instead of phi block identity

this adds O(B) retained storage and O(1) work per early operand, without another
dominator build or a per-property graph walk. The existing Lengauer-Tarjan
implementation and its provenance remain unchanged.

Availability is only one obligation. Native initialization still has its checked
ordered interval/unique normal phase corridor, actual SSA identity, no unfinished
observation and catch-copy obligations. That interval cannot reenter a phi block
dominating its allocation, so its edge copies cannot change that phi location

phi/catch storage; this change does not relax that separate contract.

`VerifyImportedPhases` still requires original import correspondence. Extending

exception or new publication premise was added here.

The separate first-own-definition gap across a selection remains open. Existing

## Initial Domain

LiteralPlan groups all live ValueOwnWrite operations by their exact allocation
OpId. The receiver must be the direct result of a live empty ordinary object
allocation, in the same basic block, earlier than every grouped definition.
Copies/phis are not guessed to be aliases: existing proved copy rewriting may
resolve them before this pass; unresolved aliases are explicit refusals.

Every definition retains the original operation, key and RHS occurrence. No
deduplication by pool index or property spelling occurs. Duplicate names must
keep definition order. Both admitted own-store and DefineField operations on
these fresh ordinary objects produce writable/enumerable/configurable data
properties. Pinned v7 provenance: RuntimeStOwnByName and RuntimeDefineField in

All RHS values must already be available at allocation: literals, language

using the object as a stored value. Cross-block uses and phi incoming uses occur
after the allocation block under fresh flow proof; same-block definitions cannot
be bypassed by a normal branch. Exceptional handlers are not introduced by this
normal-flow plan. OOM differences remain excluded only by the established source
contract, not by changing decompiler memory limits.

## Independent Check and Cost

Planning collects D definitions, sorts (allocation, definition) once, and forms
flat contiguous ranges. Verification checks supplied ranges, unique allocations,
increasing definition order, exact receivers, RHS availability and complete
one-time coverage of all live own-definitions. It then follows each allocation
value's use chain once to reject early observation. It does not regenerate or
compare against a new candidate plan. Distinct checked allocations have disjoint
result-use lists; no per-object graph scan, ancestor walk or transitive alias
closure is performed.

Beyond the shared normal-flow checker, planning costs O(O+U+D log D), checking
O(O+U+D), and additional storage O(O+D), for O operations and U uses. All scans,
sort comparisons and capacities share the invocation's remaining work/byte
grant; checker invocation does not reset the allowance. Reported retained bytes
are not whole-process peak RSS. Tests for 200/201/geometric growth and exact work
limits are written but uncompiled/unrun during the testing pause.

## Source Integration

Source rules 18 connect this proof to evaluation, the owned AST and printing:

1. A typed property arena and object expression use computed string keys
   for data definitions, including `__proto__`; never colon-style prototype
   setters, ambient Object.defineProperty, or normal [[Set]] as a substitute.
2. Evaluation pins RHS snapshots that dominate allocation. Do not inline/move a getter,
   call, closure creation, or function-name inference into a property initializer
   merely because the property's raw ValueId is available.
3. Evaluation/effect verification uses an explicit initializer placement and
   freshly verifies the supplied LiteralPlan before relocating definitions.
4. Independent TreeFlow/operand checks verify actual property order, keys,
   RHS identity and one allocation, consuming the same freshly checked plan.
5. Allocation expressions and individual property nodes carry original sites
   to separate printer position events. No generated-text provenance inference.
   Success still requires the frozen tree and publication checks to close.

The property arena has unique syntax ownership; missing, repeated or orphaned
properties refuse. Definition OpIds map to PropertyIds, not fabricated statement
positions. The CFG, SSA values, block ownership and scope identities are unchanged.
Source regression specifications cover duplicate `__proto__` keys, 200/201
properties, reordered origins, shared syntax and forbidden RHS inlining. They
remain uncompiled/unrun under the testing pause; integration is not behavioral
or real-corpus acceptance.

Buffered objects, arrays with holes/length, computed keys, later-produced RHS,
cross-block initialization, escaped receivers, prototype/descriptor mutation,
and closure captures remain separate required extensions. This initial domain
does not redefine T07 or the corpus-wide goal around easy empty-object examples.
