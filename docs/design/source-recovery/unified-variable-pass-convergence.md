# 统一变量恢复的全过程Pass收敛合同

2026-10-11设计；**已接入实际写入与域版本，完整队列/终止/成本待实现和验收，主干第4项未关闭**。
基线：`recovery_schedule.h`有15个typed pass、revision/原子提交阶段、前置清理、
no-op缓存；`binding_initializer.cc::Initializers::Run`仍手工重复调用。
共同投射求解的分析固定点与这里的优化固定点分别验收。

## P1：变更集必须来自实际提交

每个pass读取某一不可变revision，先拥有候选delta，再原子提交；提交期间禁止查分析。
引入typed `RecoveryChangeSet`，字段按语义分：值/读取替换、执行与完成、定义/初始化、
存储等价类、绑定生命期/名字、纯语法。记录受影响的ExprId/StmtId/SymbolId及旧/新事实域。
空delta不递增revision、不入队。不得用“哪个pass运行过”代替真实变更集。

字段覆盖账本必须包含BindingInitializers全部可变表：statements、omitted、
statement_values、forwarded_values、loop_declarations、primitives、literals、
read_literals、read_bindings、read_sources、aliases、storage、undefined_stores、
declaration_values、declaration_completions、replacements、transports。
evaluations/normal_stores/entry_counts是最终派生事实，不允许作为独立优化写入口。

typed delta发表层检查“实际改动 ⊆ 声明变更域”，异常/失败不能发表半份计划；
遗漏失效域、空写伪装进展属于内部错误。试算继续使用同一共同投射提供者。

## P2：失效与重跑由依赖决定

`PassContract`扩展为读域、可写域、阶段、前置义务、进展见证。
变更经单一域依赖表传递到分析：

| 实际变化 | 至少失效的共同事实 |
|---|---|
| 值或read来源、transport | expressions/flow及其联合初始化/值域解；引用/名字；live/demand/constants/copies/statements/cycles |
| 执行/控制/效果/完成/异常 | flow联合解和全部下游控制、定义、活跃、移动事实 |
| 定义/初始化/生命期 | flow联合解、initializations、live/demand、常量/复制、名字/干涉/loop entries |
| storage/aliases | 绑定投射、名字、flow联合解及下游事实；不能只失效干涉 |
| 已证明纯语法 | grammar产物；必须证明共同执行/身份/初始化不变，否则归入上面语义域 |

先保守失效整个受影响分析域，保证正确；后续才做图内区域增量，不能以增量精度
作为本轮关闭条件。每个pass按输入域epoch记录最近稳定尝试；全局revision继续
防止借用旧对象，但不得要求无关域变化后的pass无条件重跑。

去重有界队列最多容纳当前阶段15个pass。任何影响其输入/候选生成域的提交都使其
重新入队，包括提交者自身；只有证明一次调用内部已经穷尽当前候选时才可省略自身。
no-op必须记录读取的域版本。队列为空且阶段前置义务有效，才允许越过barrier。

## P3：有依赖的顺序保持显式

阶段单向推进：Values → Storage/Motion → ReadValues → Grammar。
当前合约要求晚期读取替换不反向改变已经证明的移动目的地；因此后阶段不能重新
打开storage或motion。必须证明这种分层的方向性，而不是遗漏回边后宣称稳定。

阶段内稳定优先顺序：先stored-result/惰性operand与statement规范化，再独立的
DeadDefinitions → InitialValues → Bindings，随后对应阶段的值传播、声明、alias、
snapshot/storage或read-value候选。按变更依赖重新安排，优先级不构成语义准入。
清理三步是不可越过的前置义务，不允许把中间状态标成demand已清理。

在关闭前加入反例：后阶段read替换使前阶段产生新候选。必须选择并证明以下之一：
该机会属于有意的单向规范形式且不损害规定恢复能力；或把相关值分析提前为共享事实，
让前阶段消费；或建立有终止证明的显式回边。不能私自添加固定第二轮来掩盖缺口。

## P4：终止必须有可检查的进展依据

不能使用固定轮数、规则号、deadline或work budget作为算法终止证明。
预算只负责typed资源失败；失败保留原表示/既定错误，不发表半份候选。

每类delta带进展见证：删除/transport消耗仍存活的原始执行/写入/复制义务；
合并严格减少存储等价类；值事实从未知变为已证明值；纯声明选择单向封存。
同一结果反复写回不算进展。替换链必须指向共同证明的代表元并有无环/严格秩依据，
不能靠SymbolId数值、arena顺序或名字构造语义。

尚须解决的具体阻塞：`Constants`允许替换已有literal、`BindingValues`允许再次改read
目标、`Coalesce`可把const恢复为let。简单“非空表项越来越多”不构成这些变换的全局势函数。
实现前必须把它们分别归入单调事实精化、严格缩小的等价类、单向阶段内语法封存；
无法证明者保留现有单次阶段行为并标明能力缺口，**不得因此关闭P4或整个收敛交付**。
只增加while循环不是可接受实现。

终止上界用有限原始义务数M、绑定数B、表达式/语句数E和可严格精化的事实数F表达。
要求每次成功提交消耗至少一个不可再生的见证，或严格推进有界秩；给出各类见证的
累计上界后，才能声称队列终止。测试中的迭代上限只能用于发现错误。

## P5：成本按整个过程计量

统一累计：候选扫描、队列弹出、提交、事实重建、trial、活跃事实/边传播、保留与临时字节。
报告N节点/E边/F稀疏事实/M有效提交，复杂度为各实际重建与传播成本之和；
不能拿一次分析O(N+E+F)当作整个优化过程同阶。即使轮数≤N，全图重算N次也可能是二次。

优先批量候选和输入域epoch去重。若200/201/400/800的链式机会仍触发逐节点全图重跑，
必须增加共同候选索引/受影响工作集，不能用200阈值禁用优化或降低验收。
记录密集事实真实成本，资源不足走既有typed路径；不得丢弃语义换取曲线。

## P6：独立验收与旧路径退出

1. 小型独立参考调度器枚举合法顺序直到稳定，与生产队列的共同事实和行为比较。
   输出不要求逐字相同；禁止因arena布局增加机械临时变量。
2. 检查A使B可用、B清理又使A可用、只有一个输入域改变、不相关pass不重跑、no-op
   不增版本、前置清理顺序、snapshot目的地封存、晚期回边反例。
3. 注入漏失效、忽略重入队、空delta假进展、循环替换、旧revision试算，测试必须失败。
4. 使用真实共同模型组合循环/分支/catch/活跃undefined/闭包观察/暂停保留；按原计划
   做寄存器、复制、分块、arena变化和独立源码执行。
5. 记录200/201和几何增长的全程成本及准确/差一预算。全量RSS仍暂停，不能假称通过。
6. 固定record、原名单终验后删除`Initializers::Run`手工重复pass及一次刷新分支。
   `CompletedStore`等语义证明只在共同分析接管其义务后退出，不能随队列一起粗暴删除。

关闭证据必须同时包含生产队列接入、依赖表覆盖、所有变更见证、成本及端到端结果。
设计文件、版本断言或单独的队列单元测试均不构成主干第4项交付。

### 规则309的生产接入与剩余边界

recovery_changes.h已成为全部现有优化写入的记录入口，覆盖原P1表以及原先位于
计划外的declaration_sites索引。记录拥有强类型位置及旧/新标量记录，16张可变

不创建另一份全计划before快照。日志几何扩容并计入现有预算，空间O(K)，K为
本函数单个pass最大实际写入数；snapshot比较仍有已有候选表大小的线性成本。

Schedule提交消费实际域集，各pass声明读域和可写域。no-op按域epoch核对，
而借用分析仍按全局revision核对；联合提供者仍保守整体失效。独立检查覆盖
无关grammar变化、后续batch新增Names域、旧revision、相同写入和准入失败。
200/201/400/800的写入布局和既有共同算法对照继续通过。最终定向结果为8项通过

这还没有执行P2队列，也没有P4进展证明。尤其“真实写入”可能只是重新选择
表示，不能直接当作有限进展。下一实现必须结合压平后的代表元、不可再生的原始
义务/稳定值见证及P3后阶段反例，再替换手工序列；不在旧列表外套固定轮数循环。
P5/P6整包验收仍保持本文件原合同，不因309接入而缩减。
