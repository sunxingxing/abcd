# Deprecated ISA evidence (2026-10-20)

Baseline engine and wtbase: `41f6b2a1`. No production source changes; no new
RuntimeEvidence IDs or NonExecutable refusals. The fixed 47-variant set comes
from the generated catalog, matched to real ISA entries and byte decoding.

## Profiles and encoding

The [pinned ISA version/API map](../../../references/openharmony/arkcompiler/runtime_core/isa/isa.yaml#L109)
lists 9.0.0.0, 11.0.2.0, 12.0.6.0, 13.0.1.0 and 24.0.0.0; 12.0.2.0 is also an
evidenced engine/paired-container profile. The deprecated prefix is 0xFC with
secondaries 0..46 ([ISA](../../../references/openharmony/arkcompiler/runtime_core/isa/isa.yaml#L282),
[C++ dispatch](../../../references/openharmony/arkcompiler/ets_runtime/ecmascript/interpreter/interpreter-inl.cpp#L86)).
All 47 variants are constructed and separately measured in **all six** profiles:
**282 ABCs**, cross-checked by SDK ark_disasm and the real abc_scan/abc_decode tools.
The decoder selects the generated encoding table for these profiles
([instruction.cc](../../../src/abc/instruction.cc#L42)); this is encoding evidence,
not proof that a historical frontend emitted every variant in that release.

The test-only writer now has a closed Profile enum. It counts/writes the chosen
layout directly, including reserved literal-header words for profiles above
12.0.6 ([runtime file.h](../../../references/openharmony/arkcompiler/runtime_core/libpandafile/file.h#L546),
[engine validation](../../../src/abc/header.cc#L278)); it never stamps a newer
version onto a legacy-layout blob or patches offsets afterward. The existing
12.0.6 default bytes are unchanged. Incompatible 11.0.0/11.0.1 and unknown
versions remain excluded. Header eligibility is separate from semantic policy:
profiles 9 and 11.0.2 retain **SemanticError::kUnsupportedProfile**
([capabilities](../../../include/abcd/abc/profile_capabilities.h#L41)).

## Execution-path audit

- **47/47** real C++ interpreter handlers and deprecated dispatch entries;
  **47/47** generated assembly-stub handlers and assembly-C++ implementations.
  None is a FATAL/not-implemented or dispatch-only no-op handler. Thus there is
  **no all-path NonExecutable proof** for any of these variants.
- **46/47** baseline handler entries. DEPRECATED_ASYNCGENERATORREJECT has none.
- AOT is separately limited: [Bytecodes::LAST_DEPRECATED_OPCODE](../../../references/openharmony/arkcompiler/ets_runtime/ecmascript/compiler/bytecodes.h#L316)
  is DYNAMICIMPORT (secondary 45); [the initializer loop](../../../references/openharmony/arkcompiler/ets_runtime/ecmascript/compiler/bytecodes.cpp#L863)
  therefore excludes ASYNCGENERATORREJECT (46). For the other 46 a metadata
  route exists, but [general gate construction](../../../references/openharmony/arkcompiler/ets_runtime/ecmascript/compiler/bytecode_circuit_builder.cpp#L1101)
  is not an executable lowering certificate. No dedicated deprecated cases
  are present in [SlowPathLowering::Lower](../../../references/openharmony/arkcompiler/ets_runtime/ecmascript/compiler/slowpath_lowering.cpp#L296);
  its default branch at line890 leaves the gate unchanged. No AOT execution or
  successful fallback is inferred. These gaps do not erase the interpreter paths.

(six scalar assignments, three lexical stores, CurrentEnvironment, PopEnvironment)
and **36 kUnsupportedInstruction** refusals. Profiles9/11.0.2 each give 47

for an unsupported deprecated opcode. The per-instruction probe continues
after unsupported instructions and records exact inputs, effects, normal
commits, exception exits and typed causes; recovery is the real record pipeline.

Ten variants have a successful raw lift and a complete constructed record in
the four admitted semantic profiles: POPLEXENV, TONUMBER, TONUMERIC, NEG, NOT,
INC, DEC and the three STLEXVAR widths. They become **SupportedUnverified**
under the ledger's existing limited rule. CurrentEnvironment's internal value
and the 36 unsupported variants remain Unmeasured even though decoding and raw
refusal have now been measured. **SupportedVerified remains zero.**

No runtime execution was performed: no ark_js_vm exists in the checked DevEco
SDK, build tree or PATH; the available arm64 ark_aot_compiler is a compiler,
not a JS execution oracle. The scalar/environment probes have initialized
primitive inputs; call probes deliberately supply a non-callable value, and
other minimal probes do not establish real iterator/generator/class/module/
home-object protocols. There is no claim of normal execution for such inputs.
All Node / Ark round-trip / Ark runtime oracle columns remain empty.
