# Overwritten Accumulator Writes

Class assembly removes accessor-installation consumers after original-SSA
dead-code elimination. Pure accumulator writes can remain in the final AST
even though another emitted write replaces them before any emitted read.
Rerunning original-SSA DCE would be unsound after result retargeting.

The final ElideOverwrittenAccumulator pass uses the standard local dead-store
rule on emitted operations instead. A pending accumulator write is removable
only when a later pure write overwrites it without an intervening read.
Private register reads/writes and primitive constants are admitted; allocation,
coercion, global/property access, calls and every other expression are barriers.
An accumulator read clears the pending candidate before processing its write.
Basic-block boundaries are barriers, including for successor and phi uses.

Phased SSA, catch regions, cross-block argument regions and super argument
owners are excluded. The traversal skips complete staged-call/array intervals
and treats constructor-owned nodes and fused/literal origins as barriers.
Previous-origin no-ops only alias the preceding span, and emit no reads/writes;
other previous-origin nodes remain barriers.
Class-origin metadata is only a mapping alias to an earlier class,
not an expression owner, and may survive a removed assembly copy.
No source text is inspected and no original SSA use count is modified.
Run this pass after all transformations that move emitted reads or writes.

Removed writes become NoOperation at the same PC, with origin fields intact.
Ordinary removed writes have zero-width generated anchors; class-owned nodes
retain the existing class-span alias. No instruction or PC is removed.
The traversal is O(I) for I instructions, with constant auxiliary storage and
no new dependency. It cannot delete unused register stores or recover lexical
names, source class declarations or native this bindings.

Tests, generated JS execution and RSS tracking remain paused at user request.
Deferred regressions: overwrite/read/overwrite chains, register saves of acc,
all effectful expression barriers, argument owners (including nested owners),
fused and class origin mappings, branches, catches, phased SSA and 200/201
instruction runs. Production builds and ABC-only export inspection are not
substitutes for those regressions or full application-equivalence validation.

## Production Evidence

Both production CLI targets built successfully. ABC-only pasteboard export
removed 66 assignment lines across seven files, including 23 from Home.
The eight incomplete-source / two refused / nine metadata-only record split
is unchanged, as are the 195 methods and 9,745 position entries. Entry and
method coordinates were regenerated by the printer; count preservation alone
does not establish exact range correctness. The updated export replaces
out/pasteboard-latest. Remaining register stores and lexical captures still
require further recovery before these files can be called source-style output.
