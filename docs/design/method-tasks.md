# 函数级异步、并行与懒加载

本专项设计落实根目录 [AGENTS.md](../../AGENTS.md) 的性能、函数任务与测试规则。
属于默认架构契约，从 P0/P1 开始验证；尚未实现。

## 默认请求模型

调用方使用 `MethodId` 请求解码、IR 或源码，立即获得可等待/订阅的 `MethodTask`。
提交路径只检查索引、缓存和预算；不能在提交时同步反编译整个函数或文件。
方法体读取、解码、分析和源码生成按需进行，独立方法默认可并行。
同步包装仅在调用方等待同一任务；单 worker 是调试选项。

`MethodScheduler` 管理有界任务，`MethodCache` 管理在途和完成结果。
两者都以明确的函数职责命名，不能合并成承担解析、分析和输出的通用 Manager。
候选执行器优先使用经过验证的实现；P0 比较现有可复用执行器与 oneTBB 等成熟方案，
根据取消、依赖调度、内存成本、部署和基准证据选定并固定版本，不自行研发工作窃取算法。
[oneTBB task_arena](https://uxlfoundation.github.io/oneTBB/main/specification/source/task_scheduler/task_arena/task_arena_cls.html)
提供并发上限控制，可作为执行器评估参考；引擎自己的队列和内存预算仍需单独实现。

## 索引、所有权与线程安全

文件打开阶段仅校验必要结构并建立足以定位实体/方法的共享只读索引。
方法体、debug、字面量展开和 IR 都按需加载；正确性所必需的模块/ABI/捕获元数据
可以先建立紧凑索引，但不能以“准备元数据”为由提前反编译全部方法。

任务持有文件存储和索引的共享生命周期。文件关闭禁止新的请求；现有任务或结果仍有
引用时存储继续有效，取消/完成后逐步释放。结果必须自持所需存储或拥有输出数据。
每个运行任务独占寄存器状态、IR 和 arena，发布后结果不可变。

未经证明线程安全的官方访问器在每文件加载队列中串行调用，或封装为独立 reader
实例/进程；只将按需取得的本引擎快照交给并行分析任务。串行加载不等于串行反编译，
也不要求将整个文件的方法体预先物化。分析计算不能持有文件级或全局缓存锁。

## 状态、缓存与取消

内部状态由 `enum class MethodState` 表示，至少区分排队、加载、分析、已完成、
已失败、已取消；状态变更由明确同步机制发布。展示名由 serializer 映射，禁止比较字符串驱动调度。

缓存键为文件 hash、方法实体 ID、profile、阶段、规则版本、引擎版本和相关选项的
强类型组合；相同键的在途请求共享同一计算。缓存只发布通过当前阶段 verifier 的结果。
不同阶段可以共享已完成的解码输入，而不是为源码/IR 请求各自重复读文件。

取消作用于请求订阅。某个订阅者取消不能破坏其他订阅者等待的共享任务；无剩余需求
或会话整体取消时再请求底层停止。取消/瞬时资源不足不能永久缓存成方法解析失败。
各阶段有合作式取消点，既不能每条微操作都加昂贵同步，也不能只在任务结束后检查。

缓存和在途任务均受内存预算约束；仅淘汰可回收结果，活跃引用不失效。
缓存未命中后的相同结果必须保持确定性；内存压力不能把部分结果标作完成，或改变已完成结果的语义。

## 依赖与背压

调用关系本身不要求递归反编译所有被调用函数。只有当前恢复需要的模块、外层环境、
类布局等事实才形成任务依赖；依赖通过非阻塞 continuation/worklist 驱动。
禁止所有 worker 阻塞等待同池中未调度的子任务。

对真实的元数据依赖环使用 SCC 和共享基础事实处理，避免请求 A 等待 B、B 又等待 A。
源程序递归调用、引擎任务依赖和目标语言 async 分别建模，不能混为一种图。

worker 数、在途解码数、内存占用、等待队列和输出缓冲分别有命名预算。
用户要求整个反编译进程内存不超过 1G，保守解释为 1,000,000,000 字节，
不是每个 worker 的额度。任务准入必须统筹文件驻留页、共享索引、所有 worker 的
arena、缓存、运行时依赖、线程栈和输出缓冲，预留不可直接计费的开销。
不能仅以自定义 allocator 计数声称满足限制；验收需要实际峰值 RSS，若使用
子进程则同时约束进程组总量。超过预算时背压、流式处理或落盘，不能删减语义；
资源失败是未完成，不是最终验收通过。完整批量处理不能把全部文件同时载入。
饱和时返回可等待的调度状态或明确的队列容量结果；不能无界排队或为每个方法创建线程。
大批量请求通过有背压的迭代/流式接口进入调度器。

不同函数完成顺序可不同，输出身份和文本仍按稳定规则生成。面向文件的最终结果
按稳定键汇总，逐函数通知可按完成顺序到达。不要为确定性强制所有计算串行。

## 验收

- P0 验证执行器的有界调度、依赖恢复和生命周期；P1 验证真实 ABC 的按需读取。
- 相同键并发请求只计算一次；请求一个函数不读取不相关函数体。
- 单 worker 和多 worker 的源码/IR/诊断结果一致，取消不会污染其他请求或缓存。
- 队列饱和、依赖环、文件关闭、缓存淘汰、超大方法和上游非线程安全路径不会悬挂或失效访问。
- 使用独立并发测试、TSan 与分配/读取计数验证；测试放 `tests/unit/schedule/`、
  `tests/integration/`，性能用例放 `tests/bench/`。
- 完整语料、多 worker、超大方法和缓存压力下记录峰值 RSS，必须不超过
  1,000,000,000 字节；测试报告同时列出资源失败，不能用跳过动态样本满足上限。
